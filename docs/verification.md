# Проверка приложения

Дата: **28 октября 2026 года**. Проверена production-сборка Vite, включая собранный module Worker.

Среда: macOS, arm64, **Apple M1 Pro**; Node.js 24.19.0, npm 11.17.0, Vite 8.3.5, Playwright 1.64.1, Chromium 156.0.8078.4 (headless). Браузерные эксперименты выполнялись последовательно, одним тестовым worker-процессом.

## Выполненные проверки

| Команда | Результат |
| --- | --- |
| `npm install --save-dev vite @playwright/test` | Установлены зависимости; npm сообщил 0 известных уязвимостей на момент установки |
| `npm run build` | Успешная production-сборка, отдельный Worker в `dist/assets/` |
| `npm run dev -- --port 5173 --strictPort` | Приложение запущено; HTTP 200 проверен |
| `npm test` | **5 тестов пройдены** |
| `npm run test:browser` | **9 тестов пройдены**, 29,7 с на итоговую серию |

Тесты алгоритма: сравнение с независимой `BigInt`-реализацией; инвариантность контрольной суммы к произвольным границам порций; одинаковые результаты трёх стратегий главного потока; отмена; некорректная нагрузка.

Браузерные сценарии:

1. Все четыре режима при 8 млн элементов: полное выполнение, равенство сумм, реальные интервалы кадров, ввод до завершения chunking/Worker, прогресс Worker и его завершение. **Ошибок страницы и консоли в основной серии нет.**
2. Отмена порционного расчёта при 16 млн элементов и новый успешный запуск на 1 млн.
3. Отмена Worker, проверка `terminate()` и новый успешный запуск.
4. Повтор с исходными режимом и нагрузкой; сброс истории, нажатий, метрик и эталонов; запуск после сброса.
5. Отдельные эталоны для разных нагрузок: 1 и 8 млн элементов.
6. Понятная ошибка при недоступном Worker и успешный переход к порционному режиму без перезагрузки.
7. Переключение объяснений/кода; мобильная ширина 390 px без горизонтального переполнения страницы.
8. Синхронный режим: два наблюдаемых rAF со статусом «Выполняется» до начала тяжёлой работы; реальный запрос ввода, отправленный во время расчёта, завершён после вычислений.
9. Та же проверка состояния и ввода для цепочки микрозадач.

## Реальные измерения итогового запуска

Нагрузка: **8 000 000 элементов × 128 раундов**. Сумма всех четырёх запусков: **`0x78F6DE67`**, числовое значение `2029444711`. В приложение эти измерения не встроены: следующая серия измеряется заново.

| Режим | Общее время, мс | Вычислительные участки, мс | Паузы и накладные расходы, мс | Максимальный интервал rAF, мс | Наблюдаемые кадры |
| --- | ---: | ---: | ---: | ---: | ---: |
| Синхронно | 2333,8 | 2333,7 | 0,1 | **2336,5** | 1 |
| Async / await | 2287,2 | 2285,2 | 2,0 | **2288,4** | 1 |
| Порциями | 3983,6 | 2339,5 | 1644,1 | **24,1** | 239 |
| Web Worker | 2330,1 | 2314,9 | 15,2 | **17,8** | 140 |

Единственный кадр блокирующих режимов — тот самый первый callback после вычислений. Его интервал включает заморозку, хотя сам JavaScript-монитор во время неё не выполнялся. В неблокирующих режимах обработчик кнопки отклика был выполнен при статусе «Выполняется» и прогрессе меньше 100%.

В основной серии Worker отправил **28 сообщений о прогрессе**; создан 1 Worker, вызван 1 `terminate()`. Тесты отмены отдельно проверяют завершение отменённых Worker.

Дополнительная проверка ввода показала 2215,8 мс от отправки команды мыши до её завершения для синхронного режима и 2170,9 мс для микрозадач. Это **время полного прохода команды автоматизации**, включая тестовый протокол; оно не выдаётся за задержку DOM-события, INP или отдельную метрику приложения. В тесте не используется разность `performance.now() − click.timeStamp`: в этой среде синтезированный `click` создавался уже после ожидания, поэтому такая разность скрывала задержку ранее отправленного ввода. Проверка также требует, чтобы обработчик клика увидел уже 100% прогресса.

## Границы проверки

- Это замеры одного компьютера в headless Chromium, а не обещание таких же чисел на другом оборудовании или проекторе.
- Firefox и Safari не запускались. Нативный предпросмотр через интеграцию браузера в этой среде был недоступен; браузерные проверки и скриншоты выполнены Playwright.
- Реакция на ошибку проверена через недоступный Worker. Специальные сбои ОС, обрывы загрузки файла Worker и повреждённые сообщения отдельно не инъецировались.
- Для 16 млн проверялась отмена; полный прогон предельной нагрузки 24 млн отдельно не выполнялся. Все уровни используют один и тот же алгоритм.
- Скрытие вкладки и ограничения фонового планировщика не являются частью автоматической performance-серии. Для сравнения нужна активная вкладка.
- Общее время и интервалы кадров зависят от среды; результаты не являются INP, CPU profiling или гарантией частоты отрисовки.
